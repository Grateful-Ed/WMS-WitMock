The five acts — how anything changes

POST /v1/acts/complete

Sync · 200. Finish a task — pick, pack, or count. A pick may land short (less than ordered, never zero): the line closes short and one shortage exception is raised on the order.

POST /v1/acts/flag

Sync · 200. Raise an exception against a task, order, pallet, or bin — damage, blocked location, count variance.

POST /v1/acts/post-receiving

Async · 202 + verdict. Post an ASN's receiving: pallets land at their doors, stock enters the building, the ASN closes when the last pallet posts.

POST /v1/acts/confirm-load

Async · 202 + verdict. Confirm a load: deliveries and their pallets are staged onto a trailer at a door, ready to ship.

POST /v1/acts/release

Async · 202 + verdict. New. Release a wave: every still-open order becomes released and its pick tasks come into existence — from the bin holding each item, assigned in the dataset's own pattern. Atomic: a refused release changes nothing.

Every act carries an idempotency key: a replay returns the original outcome, a reused key with a different body is refused. Async acts answer sent and land (or refuse) at the verdict — honestly, never pretending. GET /v1/snapshot reads the whole warehouse; GET /v1/changes streams what changed; GET /v1/reconcile proves the books balance.

Run it yourself

git clone https://github.com/Grateful-Ed/WMS-WitMock.git
cd WMS-WitMock && npm start          # http://localhost:8080
curl -H "X-API-Key: wms-dev-key" http://localhost:8080/v1/snapshot
